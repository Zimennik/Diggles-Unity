# UI Architecture — POCO models, DI controllers, authored views

> The as-built doc for the
> port's UI seam — the audit found the C# side undocumented (the `_RE` docs cover only the
> native ground truth). Native window laws: `BOTTOM_MENU_RE.md`, `PRODUCTION_PANEL_RE.md`;
> the UI items in `BACKLOG.md`.

## The rule

New product UI uses authored layouts (scenes/prefabs, uGUI + TMP); code supplies a
**POCO model** + a **DI controller** and a thin **View** binding seam. A view is optional —
controllers/models run headlessly (EditMode-testable) whether or not a view is assigned. UI
source comments remain English, while player-facing text resolves through `DigglesText` and the
original locale files. Code-built trees are limited to data-driven parity surfaces whose layout
is itself reconstructed from the executable: `WorkClockWidget`, `NewsTickerWidget`, and
`DocumentWindowWidget`. Do not use those exceptions as the pattern for new product UI.

## The three-layer pattern

```
Model (POCO, no Unity refs) e.g. BottomMenuModel, InventoryPanelModel, WorkClockModel
  ↑ rebuilt by
Controller (POCO, [Inject], ITickable — registered in GameLifetimeScope as an entry point)
  e.g. BottomMenuController, InventoryPanelController
  — watches engine state (ctx.SelectedHandle, SequenceActive, placement mode…),
    rebuilds the model at a throttled cadence (4 Hz + instant on selection change),
    bumps Model.Version, and dispatches clicks back into engine seams
    (get_prod_slot_list / set_prod_slot_cnt / evt_task_* / dig tools…).
  ↑ read by
View (MonoBehaviour on the authored prefab; assigned in the Inspector)
  e.g. BottomMenuView (+ BottomMenuEntryView cell prefab), InventoryPanelView
  (+ InventorySlotView), ProductionWindow, GameplayHud, SubtitleView, MainMenuView
  — spawns one cell prefab per model entry, refreshes when Model.Version changes.
```

Selection routing (native law FUN_00529360, `BOTTOM_MENU_RE.md` §1): one selected
production-class building → Production row; one adult gnome → the Inventory panel (bottom
row hides); everything else → the DIG buttons. `BottomMenuController.Tick` implements
exactly this and hides the row during cutscenes (`ctx.SequenceActive`) and placement mode.

## DI wiring (VContainer)

- `Runtime/Engine/GameLifetimeScope.cs` — the composition root: registers the runtime-built
  engine (`DigglesEngine` + `DigglesTclContext`), `SettingsService`, `IconLoader`, placement
  mode, and the entry points (`EngineTickService`, `ClickToMoveService`,
  `SelectionAuraService`, `TimeControlService`, `WorldSoundService`,
  **`BottomMenuController`**, **`InventoryPanelController`**).
- `Runtime/Engine/DigglesGameInstaller.cs` — the Inspector-wired scene components, registered
  by **explicit reference** (`RegisterComponent`), NOT hierarchy scans: AudioController,
  ScreenManager, ParticlePresenter, CutsceneCameraDriver, ElfPresenter, MainMenuView,
  GameplayHud, BottomMenuView, InventoryPanelView, plus the `DigglesClassAssetRegistry` data
  asset. Unassigned ref = feature off (warned; the two panel views are silently optional
  until authored).

Adding a new window = author the prefab → add a `[SerializeField]` view slot on the
installer → write the POCO model + `ITickable` controller → register the controller in
`GameLifetimeScope`.

## Icon / sprite pipeline (original art, nothing baked)

- **Runtime**: `IconLoader` (registered in the scope with `ctx.DataRoot`) loads
  `data/GUI/icons/<Class>.tga` on demand; `IconAlpha` conditions the alpha. Red<Class>
  variants = "not buildable".
- **Editor-baked**: `IconLibrary` (ScriptableObject) built by *Diggles ▸ UI ▸ Build Icon
  Library* (`Editor/UI/IconLibraryBuilder.cs`) via `GuiSpriteProvisioner` — the icons are RGB
  on a uniform gray color-key matte (≈164,163,150); `SharpenAlpha` does a levels remap
  (floor 6 / ceil 96) + color-extrude to recover a solid body with an AA edge
  (memory `reference_gui_icon_alpha`). Re-run the menu after adding icons.
- `ProductionWindow` resolves through `IconLibrary`; `BottomMenuView` loads at runtime via
  `IconLoader`.

## Testing

Controllers + models are EditMode-tested headlessly against the real Tcl engine (no view
needed). Views are dumb enough that Play verification is visual only. Known interaction
bug being chased: stuck `ctx.SequenceActive` / `WorkClockWidget.PointerCaptured`
click-eaters (see `BACKLOG.md`).
